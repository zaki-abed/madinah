# مكتب المدينة للخدمات المالية

نظام داخلي لإدارة الحسابات والحوالات والمكاتب والديون. يُبنى من الصفر حسب التصميم المعتمد.

- التصميم: [`docs/design/`](docs/design/README.md)
- قواعد العمل على المشروع: [`CLAUDE.md`](CLAUDE.md)

## هيكل المشروع

| المجلد | المحتوى |
|---|---|
| `web/` | الواجهة: React + TypeScript + Vite |
| `server/` | الخادم: Node + TypeScript + Fastify |
| `db/migrations/` | ملفات قاعدة البيانات المرقّمة (PostgreSQL 18) |
| `docs/design/` | التصميم المعتمد (لا يُعدَّل من هنا) |

## التشغيل لأول مرة

المطلوب على الجهاز: Node 22 أو أحدث، و PostgreSQL 18.

```bash
npm install          # 1. تثبيت الحزم
npm run db:setup     # 2. تجهيز قاعدة البيانات (يسأل عن كلمة مرور postgres مرة واحدة)
npm run create-admin # 3. إنشاء المدير الأول (يسأل عن الاسم وكلمة المرور)
```

ثم في نافذتين:

```bash
npm run dev:server   # الخادم على http://127.0.0.1:3001
npm run dev:web      # الواجهة على http://localhost:5173
```

## قاعدة البيانات

### ماذا يفعل `npm run db:setup`

يتصل بـ PostgreSQL بحساب المدير `postgres` مرة واحدة، ثم:

1. ينشئ دورين: `madinah_owner` (للـ migrations) و `madinah_app` (للتطبيق، بصلاحيات محدودة).
2. ينشئ قاعدتين: `madinah_dev` للعمل و `madinah_test` للاختبارات.
3. يولّد كلمات مرور عشوائية للدورين ويكتب بيانات الاتصال في ملف `.env`.
4. ينفّذ الـ migrations.

كلمة مرور `postgres` لا تُحفظ في أي ملف. وتشغيل الأمر أكثر من مرة آمن.

### كلمة مرور postgres

هي الكلمة التي اختيرت عند تثبيت PostgreSQL (المثبِّت يطلبها في إحدى خطواته). للتأكد منها: افتح **pgAdmin 4** من مجلد التطبيقات، واضغط على الخادم «PostgreSQL 18»: الكلمة التي تفتحه هي المطلوبة.

إذا نُسيت الكلمة، تُعاد كتابتها هكذا (في تطبيق Terminal، وكل أمر يطلب كلمة مرور الجهاز نفسه):

```bash
# 1. اسمح مؤقتاً بالدخول بدون كلمة مرور
sudo sed -i '' 's/scram-sha-256/trust/g' /Library/PostgreSQL/18/data/pg_hba.conf
sudo -u postgres /Library/PostgreSQL/18/bin/pg_ctl reload -D /Library/PostgreSQL/18/data

# 2. اكتب كلمة مرور جديدة (يسأل عنها مرتين)
/Library/PostgreSQL/18/bin/psql -h localhost -U postgres -c '\password postgres'

# 3. أعد الحماية كما كانت
sudo sed -i '' 's/trust/scram-sha-256/g' /Library/PostgreSQL/18/data/pg_hba.conf
sudo -u postgres /Library/PostgreSQL/18/bin/pg_ctl reload -D /Library/PostgreSQL/18/data
```

ثم شغّل `npm run db:setup` بالكلمة الجديدة.

### الأوامر

| الأمر | الوظيفة |
|---|---|
| `npm run db:setup` | تجهيز الأدوار والقواعد وملف `.env` (مرة واحدة) |
| `npm run db:migrate` | تنفيذ الـ migrations الجديدة |
| `npm run create-admin` | إنشاء مدير، أو إعادة تعيين كلمة مرور مستخدم موجود |
| `npm test` | اختبارات القواعد المالية وتسجيل الدخول (على `madinah_test`) |
| `npm run typecheck` | فحص الأنواع |

### قواعد الـ migrations

- كل تغيير في القاعدة في ملف جديد مرقّم داخل `db/migrations/`.
- الملف الذي نُفِّذ لا يُعدَّل: المشغّل يحفظ بصمة كل ملف ويرفض العمل إن تغيّر.
- كل migration يمنح دور التطبيق صلاحيات جداوله صراحةً. دفتر القيود وسجل التدقيق للقراءة فقط.

### رموز أخطاء القواعد المالية

القاعدة ترفع هذه الأخطاء برسالة عربية جاهزة للعرض، والخادم يعيدها بالحالة 422.

| الرمز | المعنى |
|---|---|
| `MD001` | الإلغاء بدون سبب (أو بدون مستخدم) |
| `MD002` | محاولة حذف عملية مالية |
| `MD003` | تعديل عملية ملغاة، أو تغيير بياناتها أثناء الإلغاء |
| `MD004` | حذف حساب عليه حركات، أو تغيير عملته أو رصيده الافتتاحي |
| `MD005` | كتابة مباشرة على دفتر القيود |
| `MD006` | عملة لا تسمح بفتح حسابات |
| `MD007` | عملة القيد لا تطابق عملة الحساب |
| `MD010` | كلمة مرور غير مقبولة |
| `MD011` | مستخدم غير موجود |
